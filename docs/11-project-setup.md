## Backend bootstrap

```bash
mkdir institutional-voting && cd institutional-voting
mkdir backend && cd backend
python -m venv .venv
# activate the venv for your OS

pip install fastapi "uvicorn[standard]" sqlalchemy \
  asyncpg alembic pydantic-settings \
  argon2-cffi pytest httpx
```

Add compatible versions for session management, CSRF protection, rate limiting, and any selected credential protocol. Pin final dependencies via the project's lockfile workflow.

```
backend/
├── app/ (main.py, core/, api/, models/, schemas/, repositories/, services/, workers/, tests/)
├── migrations/
├── pyproject.toml
└── alembic.ini
```

```bash
uvicorn app.main:app --reload   # --reload for local development only
```

## Environment variables

`.env.example` (placeholders only):

```
APP_ENV=development
DATABASE_URL=postgresql+asyncpg://user:password@localhost:5432/identity_db

SESSION_SECRET=replace-with-a-strong-random-secret
FRONTEND_ORIGIN=http://localhost:5173

EMAIL_PROVIDER_API_KEY=
LOG_LEVEL=INFO
```

Real deployments need separate connection settings and secrets for the election and ballot-box databases (see [22-configuration-reference.md](22-configuration-reference.md)).

Rules:

- Never commit populated `.env` files.
- Never use a known development secret in production.
- Validate required configuration at startup; fail securely if critical secrets are missing.
- Store production secrets in a managed secret store.
- Do not expose backend secrets through Vite env variables; frontend env never contains DB credentials or server secrets.

## Database migrations

```bash
alembic init migrations
alembic revision --autogenerate -m "initial schema"
alembic upgrade head
```

- Review autogenerated migrations before applying.
- Keep migrations version-controlled.
- Test upgrades from an empty database and from the previous supported schema.
- Back up production data before risky migrations.
- Never modify production tables manually without a documented migration and recovery procedure.
- Maintain a separate Alembic environment per database (`identity_db`, `election_db`, `ballot_db`).
